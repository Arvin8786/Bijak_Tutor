# Google Sheets access control and Premium Kasih setup

The React/Vite app is the learning interface. Apps Script HTML Service hosts its authenticated version; private Google Sheets stores accounts, plans and rules. Google Drive stores supporting evidence. GitHub Pages remains a static login landing page and does not receive private applications.

This release includes the implementation and an additive importer. It has **not** edited your Google spreadsheet, deployed an Apps Script project, created Google OAuth credentials, or verified sign-in against your Google account.

## 1. Create the bound project

1. Back up the existing private workbook. Open it as the owner, then choose **Extensions → Apps Script**. Keep the workbook private to trusted operators; do not publish any tab to the web.
2. Run `npm run build` locally or use the prepared deployment archive. Copy every `.gs` file from `release/` to the Apps Script project, preserving names. Create an HTML file named **App** and paste `release/App.html`. Enable manifest display in Project Settings and replace `appsscript.json` with the release manifest. CSV/JSON reports are reference files, not script source.
3. In **Project Settings → Script Properties**, enter:

   | Property | Value |
   | --- | --- |
   | `SPREADSHEET_ID` | The ID from your existing spreadsheet URL |
   | `GOOGLE_CLIENT_ID` | OAuth Web application client ID created below |
   | `ACCOUNT_ADMIN_GOOGLE_SUB` | The verified Google subject of the account administrator; see bootstrap below |
   | `PIN_PEPPER` | A long random private value generated by the owner |

   Never put these private settings in the public repository or in `VITE_` build settings. The OAuth **client ID** is a public identifier included in the login page; a client secret is not needed for Google Identity Services ID-token sign-in.
4. Run **`setupBijakLearn_`** from the editor as owner and authorize it. This creates or extends named database tabs without deleting existing records, adds missing modules and curriculum, creates a private evidence folder at the root of the owner's Drive, and installs a daily evidence-retention trigger. It is safe to rerun: existing module permissions and authored content are preserved.
5. Reload the spreadsheet. Its **BijakLearn → Initialize app and import modules** menu runs the same setup. Do not rename/reorder the generated header columns. Unexpected existing schemas stop initialization rather than silently moving data.

The manifest asks the deploying owner for Sheets, Drive, external requests, and trigger-management access. Families sign in for identity only; they do not receive access to the spreadsheet or evidence folder. Deploy from a dedicated operator account because the Drive scope is broad. `KASIH_DOCUMENTS_FOLDER_ID` is written automatically; do not replace it with a shared folder. The folder must belong to the deploying owner, sit directly in their My Drive root and have no other editors/viewers or link sharing.

## 2. Set the module rules in Sheets

`ModuleAccess` is the authoritative table. Setup imports these 18 module IDs:

| Module ID | Module | Free default |
| --- | --- | --- |
| `study-library` | Primary study library | Yes, up to 3 non-premium lessons per subject/year/stream |
| `preschool` | Preschool Studio | Yes |
| `learning-packs` | Learning Packs | No |
| `learning-map` | Learning Map | Yes |
| `learning-paths` | Learning Paths | No |
| `practice-lab` | Practice Lab | No |
| `discovery` | Discovery Library | Yes |
| `study-buddy` | Study Buddy / online tutor | No |
| `science-lab` | Science Lab | No |
| `maths-studio` | Maths Studio | Yes |
| `practice-arena` | Practice Arena | No |
| `word-tiles` | Word Tiles vs Bot | Yes |
| `activity-arcade` | Activity Playground | No |
| `junior-ai` | Junior Learn AI | Yes |
| `adult-ai` | Adult Learn AI | No |
| `junior-hobby` | Junior Creative Hobbies | Yes |
| `adult-hobby` | Adult Creative Hobbies | No |
| `parent-reports` | Parent Learning Insights | No |

Premium and Premium Kasih initially allow all 18 modules, but their checkboxes are independent. Edit:

- `enabled`: disable a module for every tier.
- `free`, `premium`, `premiumKasih`: allow that tier to open the module.
- `freeLessonLimit`: a whole-number study-library limit per subject/year/stream, ordered by lesson ID. `0` allows no Free study lessons. For other modules, no extra count limit is imposed; use their tier checkboxes. A lesson whose legacy `Lessons.premium` field is true also remains unavailable to Free.
- `notes`: your internal description; does not affect authorization.

Missing, duplicate or malformed permission rows deny access. Changes apply on the next server operation. Open modules recheck on window focus and every minute. Account approval/blocking is separate and remains required. Membership screens remain accessible so a family can apply for help even when a learning module is unavailable.

`ModuleCatalog` and `ModuleLessons` hold the four AI/hobby tracks. Setup imports their current public starter lessons too. Private growth lessons still require paid membership and `TEACHER_APPROVED`/`APPROVED` review status. Hidden lessons are never returned. The main curriculum importer adds 804 authored lessons and associated questions without claiming teacher approval.

`release/ModuleAccess.csv` is an export for inspection/manual import; run setup to seed rules safely instead of pasting over a configured sheet.

## 3. Configure Google OAuth and deploy

1. In Google Cloud Console create/select a project you control. Configure **Google Auth Platform → Branding, Audience, Data Access** (older UI: OAuth consent screen). Use your app name and support contact; start in **Testing**, add your operator and test-family accounts as test users, and request identity scopes only (`openid`, email and profile). Public launch may require Google review depending on your configuration and audience.
2. In Apps Script **Project Settings → Google Cloud Platform project**, link the standard Cloud project number if you are using it for the app’s owner consent and publication. Enable the Google Sheets and Google Drive APIs in that standard project as required. Create an OAuth client of type **Web application** under **Clients/Credentials**. Use its client ID for `GOOGLE_CLIENT_ID`. Do not create a service-account key or place an OAuth client secret in the app.
3. In Apps Script choose **Deploy → New deployment → Web app**, executing as **Me (owner)**. Choose the access setting needed for your intended Google users. All backend calls independently verify the Google ID token. Keep initial testing limited to your test accounts.
4. Add `https://script.google.com` and the **exact HTTPS origin of the deployed HTML-service iframe** to the Web client's authorized JavaScript origins. The iframe normally uses a `script.googleusercontent.com` host. Inspect the actual deployed frame URL/browser console; add the scheme and host only, with no path, query or wildcard. A static GitHub Pages origin is only needed if sign-in is later implemented there; this version redirects to Apps Script. Google Console origin restrictions and the actual deployed frame must be checked in your account; do not guess a deployment-specific host.
5. Open the deployed `/exec` URL. Verify the Google sign-in button renders and that a test-family request becomes `PENDING` in `AccountAccess`. Errors such as `origin_mismatch` or `invalid_client` require checking that exact origin/client ID pair, not disabling token validation.
6. Bootstrap the administrator: sign in with your intended operator Google account. In the private `AccountAccess` tab verify that request belongs to your operator; copy the exact text after `google:` in `accountKey` into `ACCOUNT_ADMIN_GOOGLE_SUB`. This subject is not the email address. Sign in again: **Manage account access** must appear. No user can promote themselves from the web interface.
7. Approve the test-family account. It starts on Free. In **Manage account access → Assign Free or Premium membership**, grant Free or a 1–12 month Premium period with a reason. Verify payment independently before granting Premium. Assigning Free supersedes earlier paid events. Expired/revoked memberships fall back to Free; older paid rows cannot revive access. Month durations in these controls use 30-day periods.
8. Put the deployed public `/exec` URL in the GitHub repository Actions variable `VITE_ACCOUNT_APP_URL`. Rebuild/publish using the existing Pages workflow. Keep `VITE_ENABLE_DEMO` false/unset for production. Publish an updated Apps Script deployment after subsequent backend or bundled UI changes; archive outdated deployments that share the database.

Google OAuth credentials and owner consent must be created in the owner's Google account. Repository tests use simulated Google token responses and cannot prove real OAuth, Drive permissions, Sheets access or deployed iframe behavior.

## 4. Premium Kasih: community-sponsored access

A signed-in, approved parent chooses **Membership → Apply for Premium Kasih**. The private page asks for parent/guardian name, student nickname and year, an explanation of need, guardian consent, and one or two supporting PDF/PNG/JPEG files (up to 1 MB each). Use a redacted support letter or similar evidence; do not request full identity documents, bank statements or unnecessary financial details. The public demo has no personal-data input/upload form.

The backend validates consent, lengths, file size/type/signature, ownership and duplicate requests. It stores details/status in `Scholarships` and files in the owner-only Drive folder, referenced by private IDs. Only the verified administrator can list applications or download supporting files through the backend; no shareable Drive links are created. Applications are limited to three per account per 30 days. Submission never changes membership.

In **Manage account access → Premium Kasih applications**, the operator downloads evidence, records a review note, and approves a 1–12 month sponsorship or declines the application. Approval writes `PREMIUM_KASIH` to `Subscriptions` and records the decision in `Audit`. Account blocking continues to override membership. Legacy evidence-free scholarship requests cannot be approved until a complete application is submitted (decline the legacy request first).

A daily owner trigger calls `purgeKasihEvidence_`: evidence is moved to Drive Trash and personal application text is removed 90 days after final review. Drive Trash is not permanent deletion; the owner must follow their retention policy for emptying Trash. Pending applications remain until review; review them promptly and handle early deletion requests directly in the private workbook/Drive. The service needs an operator contact/privacy notice and a real-account permission test before collecting documents from families.

## 5. Checks before using real accounts

Use fictional evidence and two test Google accounts to verify:

1. Wrong Google audience/issuer, expired tokens and unverified email are rejected.
2. Unapproved accounts are pending; only the operator can activate/block them.
3. A Free user cannot open a disabled module or fetch/submit a lesson outside the Free limit. Change Sheet rules and confirm the next request reflects them.
4. Premium and Premium Kasih use their separate permission columns. Expiry/downgrade returns the family to Free.
5. A family can submit their own application but cannot list another family's application or download evidence. Repeated pending requests and disguised/oversized files are rejected.
6. Administrator approval grants sponsored access; decline does not. Blocking an approved family prevents its next protected request.
7. The private Drive folder and every uploaded file have no link sharing or other viewers/editors. Check the daily retention trigger in Apps Script **Triggers**.

Development validation: `npm test`, `npm run build`, and the browser smoke suite. The browser suite checks tier denial, file selection/submission, evidence download, approval and Free assignment against a simulated backend; VM tests exercise the Apps Script authorization logic.

The JavaScript bundle includes existing public learning assets and client-side activities. These are not DRM-protected by a UI gate. Private records, evidence and backend operations are server-authorized; confidential/premium-only lesson assets must be removed from the static bundle and served exclusively by authenticated endpoints before claiming content secrecy. Existing teacher-review, child-identity separation and assessment anti-replay limitations still apply.
